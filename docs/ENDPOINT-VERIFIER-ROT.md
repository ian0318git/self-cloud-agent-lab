# endpoint 安全驗證器的已知鏽

**現勘：2026-09-30；第 4、5、6 支於 2026-10-01 重勘（D-076）。** 對象是 uv 安裝的
`endpoint-vps 0.1.2`：

```
~/.local/share/uv/tools/endpoint-vps/lib/python3.13/site-packages
```

## 這份文件為什麼存在

endpoint 的安全工作是一疊刀做出來的，每一刀的驗證器都是**對著「當時那棵樹」**寫的。
後面的刀會合法地搬動前面的刀釘住的檔案。所以今天八支裡**三支失敗、一支被擋住** ——
而**這些紅全部是過期的釘值或過期的定位字串，沒有一個是活著的缺陷**。
（2026-09-30 初勘時是四支失敗；D-076 解掉了其中一支，見下。）

沒有這份清單，下一個讀者分不出「已知的鏽」與「新的損壞」。那是這份清單唯一的用途。

**而「樹沒有壞」不是這裡的判斷，是一個可以自己跑的檢查。** 樹上四個受影響的檔，
`sha256` 全部落在 `scripts/` 底下那 36 個釘值裡，而且各自落在自己那條鏈的**末端**
—— 見〈疊放鏈〉。紅的是驗證器，不是樹。

**它不管的事：不修。** 這些驗證器是「當時檢查了什麼」的記錄。把驗證器改到會過，正是
D-033 的教訓 —— 改規則讓紅變綠，跟它要抓的蟲是同一件事的鏡像。要重新取得覆蓋，是
**新寫一支**、或明講地更新舊的並記下為什麼，不是把它改成綠的。

**2026-10-01 追加（D-076）：上面那句留的兩條路，有一條被走了。** 第 4 支的檢查 A
走的是「**明講地更新舊的並記下為什麼**」，而記在 `DECISIONS.md` D-076。走之前先把
「根因一」裡的三種釘值拆成**兩種**（見〈根因一〉末）—— 因為它們**不是同一種東西**，
而原先那段把它們寫成同一種，這個區分是 D-076 的主要產出。

## 疊放鏈

各套用腳本自己說明的順序是：**ntfy → stop → 切 B → 切 C**（`apply-endpoint-topic-secret.sh:392`、
`apply-endpoint-tunnel-url-privacy.sh:191,199,207`）。切 A 與第四刀動的是 `engine/engine.py`。

把六支套用腳本的釘值排開，**四條鏈各自都是連續的** —— 後一支的 `PRISTINE` 逐字等於
前一支的 `PATCHED`，中間沒有缺口：

| 檔案 | 鏈（每一格是「哪一刀：結果」） |
|---|---|
| `engine/engine.py` | 起 `871b4cab` → 切A `68dfa5a2` → **第四刀 `1930dda1`** |
| `endpoint/commands.py` | 起 `618a8f00` → stop `d8b7cd81` → 切B `8d6f2ade` → 切C `19b8129e` → 第四刀 `abd6d3c9` → **D-073 `bcd0f287`** |
| `endpoint/core.py` | 起 `c482400a` → stop `2e8692b1` → 切B `8c8afbb9` → **切C `e3d7fe21`** |
| `scripts/master_build_notebook.py` | 起 `1d927451` → ntfy `b416bd47` → 切B `a0449014` → **切C `e29a23aa`** |

**樹上實得 —— 四個檔都落在自己那條鏈的末端：**

| 檔案 | 實得 | 是誰的 `PATCHED` |
|---|---|---|
| `engine/engine.py` | `1930dda1…` | **第四刀的** |
| `endpoint/commands.py` | `bcd0f287…` | **D-073 的** |
| `endpoint/core.py` | `e3d7fe21…` | 切 C 的 |
| `scripts/master_build_notebook.py` | `e29a23aa…` | 切 C 的 |

⚠️ **`commands.py` 那一列是 2026-10-01 補的，不是 D-076 造成的。** 初勘（09-30）把它
寫成「第四刀 `abd6d3c9` ＝ 末端」，那是**錯的**：`endpoint-boot-honest-outcome.patch`
（D-073）也動這個檔，把它推到 `bcd0f287`，而它的雙向釘值就寫在
`apply-endpoint-boot-honest-outcome.sh:67-68`（`PRISTINE=abd6d3c9`、`PATCHED=bcd0f287`）。
**是這份文件落後了一刀，不是樹漂移了** —— 樹上的實得值一直都是它自己那條鏈的末端，
只是那條鏈在文件寫完之後又長了一格。這正是本文開頭那句「後面的刀會合法地搬動前面的
刀釘住的檔案」再發生一次，而**這次連這份清單本身都被搬到了。**

**這是這份文件最重要的一張表。** `scripts/` 底下所有 64 位十六進位常數（36 個）去重
之後，**樹上的四個檔全部落在這個集合裡**，而且是各自那條鏈的末端。**沒有一個檔漂移。**
（2026-10-01 重量：集合是 **36**，初勘寫的 35 在當天就已經少了 —— 變的不是這一輪碰過的
那兩個值，它們是 1 換 1；多出來的那個是 D-073 的套用腳本帶進來的。又一次「文件落後
一刀」。數這個集合的指令在〈無測試聲明〉，可以自己重跑。）

**所以樹是對的，紅的是驗證器。** 這句話就是「鏽」與「損壞」的分野，而它不是推論
—— 把四個檔的 `sha256` 拿去對那 36 個常數就是它全部的證據。D-070 也**獨立**記下了
同一組數字：「安裝樹的兩個檔案雜湊與本節釘住的 `PATCHED` 值逐位元相符 —— `engine.py`
`1930dda1…`、`commands.py` `abd6d3c9…`」。（引文照抄；`commands.py` 今天已是
`bcd0f287`，見上表。）

**第四刀不是偷偷走過去的。** `apply-endpoint-apikey-selfheal.sh:55-64` 有完整的雙向
釘值，它的 `PRISTINE` 正是切 A 與切 C 的 `PATCHED`（`68dfa5a2`、`19b8129e`）——
它是一個閘門，而且它**過了**。會壞掉的是**前面幾刀的驗證器**：它們釘的是「那一刀
剛套完的樣子」，而鏈已經往前走了。

**（第四刀內部的定位方式是另一回事** —— 那是它的補丁怎麼描述自己要改哪幾行，與
**套用腳本釘不釘 sha** 無關。這兩件事在這一輪被混為一談過一次，所以在這裡分開寫。）

## 只有兩個根因

### 根因一：驗證器釘在鏈的中間，而鏈往前走了

第四刀改了 `engine/engine.py` 與 `endpoint/commands.py`（D-073 又動了後者一次），
於是那些**釘在第四刀之前**的檢查就全部失效 —— 不是釘錯了，是**釘在過去**：

- 釘住 `engine.py` ＝ `68dfa5a2`（切 A 修補後）的檢查 → 樹已經是 `1930dda1`
- 釘住 `commands.py` ＝ `19b8129e`（切 C 修補後）的檢查 → 樹已經是 `bcd0f287`
- 釘住別支驗證器**檔案本身**的 sha、而那支驗證器後來被合法編輯過的檢查 → 失效
  （第四刀讓 `test_endpoint_apikey_broadcast_fixes.py` 必須改：它原本錨在 `APIKEY:`
  分支上，而第四刀把那個分支刪了）

**前兩種不是「值錯了」。** 每一個釘值在寫下的當天都是對的，而且今天仍然**正確地
描述著「那一刀剛套完的樣子」** —— 只是樹已經不是那個樣子了。要讓它們變綠就得改數字，
而**改數字就是重寫歷史**：那個釘值記錄的是「這一刀套用之後我量到什麼」。改掉它，
D-067～D-070 的驗證紀錄就不再是當時的紀錄，而會變成一份**對著今天的樹回頭校準過**的
文件。這是「不修」在這一類上最具體的理由 —— 比原則更硬。

#### 但第三種不是前兩種 —— 這是 D-076 的產出（2026-10-01 追加）

初勘把三種寫成一類，**那是這份文件自己的錯**。前兩種與第三種問的是不同的問題：

| | 前兩種（`ENGINE_SHA`、`commands.py` 的兩個釘值） | 第三種（`CUT_A_VERIFIER_SHA`、`CUT_B_VERIFIER_SHA`） |
|---|---|---|
| 它記錄什麼 | **某一刀套完之後，樹長什麼樣** | **那支被信任的守衛，現在是不是同一份位元組** |
| 它回答的問題 | 「樹還是切 A 留下的那份嗎？」 | 「守衛有沒有被動過？」 |
| 性質 | **歷史紀錄** | **現況的絆線** |
| 漂移代表什麼 | 樹往前走了（正常） | 有人編輯了守衛（要交代） |
| 更新它 | **等於重寫歷史，不可以** | **等於重新認證，可以，但要量給你看** |

第三種的用途**寫在它自己的檔頭裡**：*"if this hash moves, someone edited the guard to
accommodate a later cut, and its independence is gone."* 它是一條絆線，不是一張照片。
絆線被觸發之後有兩條路：**認定守衛不可信而放棄它**，或**重新認證它、把絆線移到新位置**。
第二條路不是免費的 —— 移完之後，絆線**再也不能告訴你「第四刀改過它」**了，那個事實
改由檔頭註解與 D-070／D-076 承載。**這是一個真的損失，不是換個寫法。**

所以 D-076 走第二條路時，代價是這樣付的：

1. **重跑雙向**：對修補後的樹 rc=0；對 `tmp/precut-a/` rc=1（紅在檢查 A）。
2. **補上它原本缺的突變台**（第 9 支）：5 條指名突變 ＋ 1 條守門 ＋ 1 條走檢查 B
   第二條路徑，**每一條都被指名的那一句抓到**。這一步才是「重新認證」的實質內容
   —— 在此之前它只有分辨力，沒有「抓得住每一件它宣稱要抓的事」的證據。
3. **同一輪不動前兩種。** `ENGINE_SHA`（`68dfa5a2`）與切 C 的 `commands.py` 釘值
   **原封不動留在紅的位置上**，而這正是上面那張表在做事、不是在找理由的證據。

**檢查 B 有一條斷言沒有被突變涵蓋**（`TUNNEL ACQUIRED:` 分支必須 `break`）。原因是
突變台的表格格式要求單行錨點，而那個 `break` 在 `run_boot` 裡出現 3 次、不唯一。
**它是被斷言了、但沒有被突變測過的一條**，記在第 9 支的檔頭與 D-076 的「沒有量到的」。

**受影響：第 4 支的檢查 A、第 5 支的 D8／D9／D11／D13×3。** D13 的三項不是獨立缺陷 ——
切 C 的閘門因為 `commands.py` 的釘值對不上而拒絕套用，閘門根本沒跑到能回答問題的地方。
閘門拒絕時自己也把原因印出來了：

```
✗ endpoint/commands.py 既不是已知的原始版，也不是修補後的版本。
  預期原始版雜湊：8d6f2ade…
  實得：          abd6d3c9…
```

### 根因二：定位字串／假命名空間被後來的刀拿走

- **第 7 支的檢查 B、C**：`NameError: name 'topic_secret_of' is not defined`。
  切 C 讓 `run_stop()` 多了這個依賴（樹上 `commands.py:60` 匯入、`:1529` 使用），
  而驗證器 exec 那段程式碼時的**假命名空間沒有跟著更新** —— 它裡面 `topic_secret_of`
  出現 **0 次**（已查）。**B、C 兩項因此從來沒有執行過**，不是執行後失敗。
- **第 8 支的節流檢查**：`StopIteration`。它用兩個標記夾出產生器吐出的 `signal()`，
  結束標記是 `def broadcast(url)`。**那個函式被切 B 整段刪掉了**（`DECISIONS.md:10171`、
  `:10273`），所以結束標記找不到。樹上的產生器已經沒有 `broadcast` 這個字（已查）。

**這兩項都是「大聲的」失敗** —— 驗證器把例外接住、印出「無法執行」、並列進未過清單。
不是靜默跳過。這是它們可以被信任的地方：**紅，而且說得出為什麼紅。**

### 第 4 支：`test_endpoint_tunnel_url_privacy.py` —— **已解除（2026-10-01，D-076）**

檢查 A 釘的是**切 A 那支驗證器檔案的 sha**，用來確認「這支驗證器沒有被動過，所以它

```

✓（其餘 20 項，共 22 個 ✓、0 個 ✗）
```

## 怎麼分辨「已知的鏽」與「新的損壞」

重跑一次（指令見下），拿輸出跟上面比對。規則：

1. **已知的鏽講的是「找不到」或「對不上」。** 錯誤訊息裡會指名一個具體的東西：一個
   sha、一個 `NameError` 的名字、一個找不到的標記。它描述的是**驗證器與樹的關係**。
2. **新的損壞講的是「行為不對」。** 錯誤訊息會說某個斷言不成立 —— 閘門放行了不該放行
   的、某個推導得到錯的值、某個計數不等於預期。它描述的是**樹本身**。
3. **數目不一樣就是有事。** 第 4 支應該恰好 **0** 項、第 5 支恰好 **5** 項、第 7 支
   恰好 2 項（而且必須是「無法執行」）、第 8 支恰好 1 項、第 6 支的對照組恰好印
   **5** 行。**比表上多，就是新的。**（2026-10-01 之前是 1／6／2／1／6；第 4 支與
   第 5 支少了的那一項是同一項，D-076 解掉的，見〈逐項〉。）
4. **這一輪沒驗過的事，不要當成驗過了。** 例如第 6 支解掉鏽之後會不會過 ——
   **到 2026-10-01 為止仍然沒驗過**，而它擋在 D9／D11 後面，那兩個是刻意不動的。

**真正的判準是**：這三支的紅都指向「驗證器跟不上樹」，而不是「樹壞了」。**如果哪天
某支紅了、而它的訊息在說樹的行為不對，那份清單幫不了你 —— 那是真的。**
（第 3 條那個「閘門放行了不該放行的」聽起來正是這種訊息，但它不是：**先確認閘門有沒有
走到那一步。** 第 5 支的 D13 就是這樣 —— 在 sha 前置條件就回 1 了，那句話問的問題
